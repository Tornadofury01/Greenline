# Farm game plan (G1)

"Try a plan on your own field, one season at a time." The **Farm simulator** (More → Farm simulator, screen id `sim`) IS this isometric (2.5D) farm game; the old chart-based simulator (plan editor, line charts, 2040 weather choices, profit band) was removed in G2d. It runs on the farmer's real field, with real past monthly weather, through the existing engine.

The game **only reads** `scoring/engine/`, `scoring/modelSlots.js`, `content/model-placeholders.json`, `/pipeline` and `/shared`. It changes none of them.

## How the engine runs for the game
- **Screen:** `app/src/screens/FarmSimulator.jsx` (screen id `sim`, in the "More" menu) lazy-loads `game/FarmGame.jsx`. Its start screen (`game/StartScreen.jsx`) is the landing page: hero preview, how it works, Free play, challenges.
- **Running a plot:** `game/gameWorker.js` runs `buildPlan` / `engineConfig` (`sim/simSetup.js`), then `createSimulation` (`scoring/engine/simulator.js`), then calls `step()` once per day, for one plot. `game/runSource.js` is the single place the game gets its numbers (engine only since G2c).
- **Daily output** (one Float32Array per column):
  - weather: `rain`, `tmax`, `tmin`
  - water: `irr`, `rz`, `rzCap`, `stress`, `drain`, `runoff`
  - crop: `canopy`, `biomass`, `stage`
  - soil: `ground`, `residue`, `eros`, `som`
  - nitrogen: `minN`, `nFix`
  - money: `profit` (running total)
  - pests: one column for each of the 6 pests
  - which crop: `cropIdx`
- **Per-crop output (`episodes[]`):** yield, `yieldVsTypical`, stress days, heat and frost, `killed`, `pestLossByPest`, revenue.
- **Per-year output (`yearly[]`):** runoff, erosion, bare days, N leached, SOM.
- **Speed:** the selftest requires under 100 ms per season. The game can compute the whole season first and then animate the daily arrays over about 20 s.

## Player choices (only the ones the engine fully calculates)
| Choice | Status |
|---|---|
| Cash crop | works, in the game |
| Cover crop species | works, in the game (always ended at planting) |
| Tillage: full / reduced / no-till | works, in the game |
| Nitrogen rate | works, in the game (one rate for every cash crop) |
| Irrigation: none / limited / full | works, in the game |
| Planting date (±14 days) | works, in the game |
| Cover end date | partly: only "early" works, and "none" does nothing in the engine. **Not in the game** |
| Variety (full / short maturity) | partly: changes the heat sum but not the end date. **Not in the game** |
| Double crop | partly: the engine can run it, but the plan builder (`sim/simSetup.js`) can't set it up. **Not in the game** |

## The 8 meters
All 8 animate from the worker's daily arrays.

| Meter | Engine output |
|---|---|
| Crop growth | `canopy`, `stage`. End of season: `episodes[].yieldVsTypical`. Water `stress` and heat/frost are shown as warnings on this meter |
| Soil water | `rz / rzCap` |
| Ground cover | `ground` + `residue` |
| Soil loss | running total of `eros` compared with the soil's T value. End of season: `yearly[].erosion` |
| Soil health | `som`. End of season: `soil` trend |
| Nitrogen | `minN` (+ `nFix`). End of season: `yearly[]` N leached |
| Pests | the 6 pest columns. End of season: `pestLoss` |
| Money | running `profit`. End of season: `episodes[].revenue`, `totals` |

## Season events and fit checks
- **During the season:** events come from the season's own data: a run of dry days (`stress`), a frost or heat kill (`killed`, frost/heat factors), a pest spike, a heavy-rain runoff day.
- **At the end:** run the same `waterCheck`, `diseaseCheck`, `marketCheck` and `seasonCheck` (`scoring/v2/fitChecks.js`) and `scoreOption` (`scoring/v2/scores.js`). They are called unchanged, with `metricsOf` (`scoring/v2/metrics.js`).
- **What the checks need:**
  - the farm's current rotation as `base`
  - 4 climate-scenario runs
  - a new `fit` message in the worker
  - cost: about 1–2 s, shown as "Checking your plan…"
- **Market check:** `cropFieldShare` is null in the app, so the market check carries the placeholder tag.
- **Fallback if the live checks slip tonight:**
  - loaded v2 plans show their precomputed `fitChecks` / `scores`
  - player-built plans show only the season events above

## Weather years
- **Data:** monthly weather for 2008–2025. All 300 fields share one series. Daily weather is generated by a seeded generator that keeps the real month totals, so the label says "real monthly weather, daily pattern simulated".
- **Picking years:** Free play draws 5 random past years from `pastYears()` (`sim/simSetup.js`); each challenge has its own fixed 5 years (`CHALLENGES` in `game/plots.js`). There are no future (2040) weather choices in the game.
- **Year labels:** Model C labels are drought / hot / wet / normal. The placeholder only marks 2000 and 2011 as drought and 2015 as wet; "hot" is never used. The label always carries the "placeholder, model coming" tag.

## Placeholder tags
- The game worker passes `modelFile: null`, so all 5 model slots are placeholders.
- The game shows `PlaceholderTag` (`components/PlaceholderTag.jsx`) next to anything that rests on the run's `placeholderSlots` (e.g. the year-type label).

## Challenges (replay goals, checked from worker output)
- Finish 2011 with profit above $0.
- Keep soil loss under T for 3 seasons in a row.
- Fewer than 40 bare days in a year.
- End with higher SOM than you started.

## "Play this plan"
- **New state:** `playPlan` / `setPlayPlan` in `state/AppContext.jsx`.
- **Buttons:** on `StrategyCard` in `screens/Plans.jsx` (Compare re-exports it) and in `components/OptionCard.jsx`. Each sets the plan and calls `setScreen('sim')`.
- **Converting the plan:** `planToSim()` in `game/playPlan.js` turns `option.sequence` + `management` into simulator `crops` / `controls`.
  - It takes the first main crop and cover in each year.
  - The average N becomes a flat rate, with a note.
  - Double crops are dropped, with a note.

## Tech
- **Engine:** **PixiJS v8** rather than Phaser 3. We only need a renderer (no physics or scene system), it's smaller (about 500 KB vs about 1 MB), and it fits easily inside a React component.
- **Loading:** `await import('pixi.js')` runs only when the game opens.
- **PWA precache:** the limit is `maximumFileSizeToCacheInBytes` 4 MB per file, and the main bundle is about 1.36 MB today.
  - Add the game chunk to `globIgnores` and cache it at runtime, so the offline precache doesn't grow.
- **Art:**
  - Draw iso tiles, crop rows, cover and residue in code (Pixi `Graphics`).
  - Kenney.nl CC0 packs are optional if they download cleanly. We haven't checked that yet.
  - No art from Cornucopia or any other game.

## Risks and gaps
- **Fit checks for a player-built plan** are the slowest, most fragile part. The fallback above is ready.
- **Old field file:** the game worker reads `shared/fields/<id>.json`, not the v2 file.
- **Placeholder year types:** they're placeholders and "hot" is never assigned.
- **Cover end date, variety and double crop** stay out until the engine or plan builder supports them.
- **Time:** build the meters and the engine wiring first, then the animated scene.

## G2b: the playable 4-plot game (Nov 15 2026)
- **Shape:** full-screen isometric canvas (`game/scene.js`, `GameCanvas.jsx`) with 4 plots. Toolbar (`Toolbar.jsx`): seeds, cover, tillage / fertilizer / water (set in year 1, locked after: the engine runs one management per plot run), quick fill. Season playback per plot (`season.js`, `SeasonView.jsx`), pop-ups with source, tap a plot for live meters. Harvest coins + scoreboard (`Scoreboard.jsx`). Challenges with stars saved on the device, end screen (`EndScreen.jsx`, rules in `plots.js`).
- Numbers were mock in G2b; G2c replaced them with the engine (below).
- **Year-1 disease fix:** `playedStructure()` in `plots.js` compares only played years in order (year 1 vs the field's last CDL crop), instead of `structureOf()`'s loop that compared a one-year plan with itself. Used by the worker for both the disease check and the pest score.
- **Scene rules:** a plot with a live crop is never drawn as bare soil (minimum seed / sprout); dust, cracks and gullies only on plots the run marks bare.

## G2d: the game is the Farm simulator (Nov 15 2026)
- Removed the chart simulator completely: `screens/Simulator.jsx`, `components/SimCharts.jsx`, `sim/simView.js`, `sim/simWorker.js`, `sim/useSimRuns.js`, its CSS and its i18n keys (only `sim.in.tillageOpt` / `sim.in.irrOpt` stay, the toolbar reads them). `sim/simSetup.js` stays (the game worker and toolbar use it).
- No "Simulator | Play" switch: More → Farm simulator opens the start screen. "Play this plan" (Plans / Compare) shows a "Ready to test" card there.

## G2c: the game runs on the engine (Nov 15 2026)
- **No mock:** `game/mockRuns.js`, `USING_MOCK` and the "Mock numbers" line are gone. `npm run selftest` runs `app/scripts/check-no-mock.mjs`, which fails if a mock file, flag or the `game.mock` text comes back.
- **Runs:** `game/runSource.js` keeps a pool of 2–4 `gameWorker.js` workers. Each season = one engine run per plot + one hidden run of the current rotation (baseline), all on the same real weather years (`weatherYears`, replayed from year 1 so soil, residue and pests carry over). Scores and fit checks on the main thread: `scoreOption` + `waterCheck` / `diseaseCheck` / `marketCheck` (`regional: null`) / `seasonCheck` (no 2040 scenarios), unchanged.
- **Costs:** the toolbar's setup cost is the engine's own ledger for this season (`setupUsd`: planting, seed, N, pre-plant pass / no-till planter, fallow weed control), from a quick engine run of each plot as set; "—" until it arrives. `plots.js setupCost()` (a hand copy of the engine's cost lines) was removed. Coins = game budget ($300/plot, a named game setting) + the engine's money per season.
- **Baseline / quick fill:** best plan and current rotation come from the field's v2 file (`buildMergedPlans`, as on the Plans page). No real v2 file (or the sample) = those quick-fill buttons are hidden. Baseline falls back to the USDA crop history (slot A); with neither, the Risk meter shows "—".
- **Files the game reads per field** (all through the app's loaders, any field id):
  - `shared/fields/<id>.json` via `data/loadField.js` (the app's field; weather, soil, market, CDL history)
  - `shared/v2/models/<id>.json` via `data/loadModels.js` → `makeSlots()` (missing = placeholders, tagged)
  - `shared/v2/fields/<id>.json` via `data/loadV2.js` (quick fill + baseline only)
  - A field without monthly weather shows "No data here yet".
- **Speed:** one plot-season in the worker takes 8–32 ms on the dev laptop (5 seasons replayed in year 5); the 4 plots + baseline run in parallel. The "Growing the season…" sprout shows for at least 0.4 s.
